Jak to funguje

Výřezy jsou v pořadí hlavních operací: načtení seznamu, vytvoření, aktualizace a kontrola přístupu.

Normální stopa

query.team_id=None → poslední aktivní tým je 3 → tým je aktivní a user je člen → vznikne TaskFilters(team_id=3, ...) → repository vrátí seřazené úkoly.

Chybová stopa

Výslovně zadaný neaktivní tým, neexistující tým i cizí tým končí stejným TaskAccessDeniedError. Service tak navenek nerozlišuje, která přístupová podmínka selhala.

Normální stopa

Repository najde poslední pozici ve stejném statusu, service přičte jedna a případně nastaví UTC začátek práce. insert_task pouze provede db.add; objekt zatím není commitnutý.

Chybová stopa

Současné requesty mohou oba přečíst stejnou poslední pozici. Databázová unikátnost (team_id, status, position) pak jeden commit odmítne; endpoint zachytí IntegrityError, provede rollback a vrátí conflict. Service sama tuto race condition neuzamyká.

        # Validates the business rule that you can't have should_review True if no reviewer is assigned and vice-versa
        should_review = updates.get("should_review", task.should_review)
        review_date = updates.get("review_date", task.review_date)
        if not should_review and review_date is not None:
            raise ApiConflictError("Task with no review cannot have a review date")
        if should_review and reviewer_member_id is None:
            raise ApiConflictError("Can't review task with no reviewer")
        if not should_review and reviewer_member_id is not None:
            raise ApiConflictError("Can't assign reviewer to task that shouldn't be reviewed")

        return update_task_repository(task, updates)

exclude_unset=True zachová PATCH semantiku: chybějící pole se nemění, explicitní null může vztah odstranit. Kontrola review pravidla kombinuje nové hodnoty se stávajícím stavem Task; poté repository nastaví jen přítomná pole.

Chybová stopa

Odebrání reviewera bez současného nastavení should_review=False vytvoří výslednou kombinaci „review požadováno, reviewer chybí“ a skončí ApiConflictError ještě před mutací objektu.

4. Přístup k jednomu Task je samostatná brána

backend/app/services/tasks.py:137-152 
    def get_accessible_task(self, db: Session, task_id: int, user_id: int) -> Task:
        task = get_task_by_id(db, task_id)                  
        if not task:
            raise TaskNotFoundError()

        team_id = task.team_id
        if not is_team_member(db, team_id, user_id):
            raise TeamMembershipError()

        team = get_team_by_id(db, team_id)
        if team is None:
            raise TeamNotFoundError()
        if not team.is_active:
            raise TeamInactiveError()

        return task

GET jednoho úkolu, PATCH i DELETE sdílejí tuto bránu. Vrací spravovaný SQLAlchemy objekt, který PATCH následně mutuje a DELETE předává db.delete.
