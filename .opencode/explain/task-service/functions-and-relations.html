Kapitola 4

Funkce a jejich vazby

Úplná reference definovaných metod a přímo volaných projektových funkcí; graf pod ní záměrně ukazuje jen architektonicky podstatné vazby.

Funkce uvnitř souboru

get_all_tasks

def get_all_tasks(self, db: Session, session: UserSession, query: TaskQuery) -> list[Task]:

Orchestrace načtení seznamu: nejprve vytvoří autorizované TaskFilters, potom deleguje dotaz. Patří sem, protože caller nemá znát přístupové předpoklady repository filtru.

create_task

def create_task(self, db: Session, active_team_id: int, user_id: int, payload: TaskCreate) -> Task:

Koordinuje WIP limit, týmové identity, pozici a čas začátku práce a nakonec přidání Task do session. Jde o hlavní write entry point; mechanické sestavení modelu přenechává repository.

update_task

def update_task(self, db: Session, task: Task, payload: TaskUpdate) -> Task:

Sloučí částečný payload se stávajícím stavem, ověří týmové identity a review invariant a teprve pak mutuje Task. Tato hranice potřebuje zároveň validovaný vstup i perzistentní stav.

get_accessible_task

def get_accessible_task(self, db: Session, task_id: int, user_id: int) -> Task:

Načte Task a ověří členství, existenci týmu a jeho aktivitu. Centralizuje přístupovou bránu společnou pro GET detailu, PATCH a DELETE.

_resolve_task_filters

def _resolve_task_filters(self, db: Session, session: UserSession, query: TaskQuery) -> TaskFilters:

Převede volitelný tým z query na povinný a autorizovaný team_id a ověří případný assignee filtr. Je privátní, protože výsledný filtr je interní kontrakt mezi service a repository.

_can_create_in_progress_task

def _can_create_in_progress_task(self, db: Session, team_id: int) -> bool:

Ověří aktivní tým, načte globální limit a porovná jej s počtem týmových IN_PROGRESS Task. Vrací bool pro větev create; chybějící konfigurace a neplatný tým jsou samostatné chyby.

Externí funkce

find_tasks

def find_tasks(db: Session, filters: TaskFilters) -> list[Task]:

Sestaví SELECT pro tým, volitelné statusy a assignee a řadí podle statusu, pozice a ID. Je to persistence hranice pro list operaci.

get_task_by_id

def get_task_by_id(db: Session, task_id: int) -> Task | None:

Provede primární lookup přes db.get. Service nad návratovou hodnotou doplní doménovou chybu a autorizaci.

count_team_tasks_by_status

def count_team_tasks_by_status(db: Session, team_id: int, status: TaskStatus) -> int:

Vrátí agregovaný počet Task ve stavu; None ze scalar převádí na nulu. Poskytuje aktuální vstup pro rozhodnutí o WIP limitu.

get_last_task_position

def get_last_task_position(db: Session, filters: TaskFilters) -> int | None:

Najde nejvyšší pozici ve zvolených statusech, při prázdném seznamu používá TODO. Create mu vždy předá právě status payloadu, aby mohl nový Task zařadit na konec sloupce.

insert_task

def insert_task(db: Session, team_id: int, creator_member_id: int, payload: TaskCreate, position: int, started_working_at: datetime | None) -> Task:

Sestaví SQLAlchemy Task, přidá jej přes db.add a vrátí jej bez commitu. Service dodává již rozhodnuté doménové hodnoty; endpoint vlastní transakci.

update_task

def update_task(task: Task, updates: dict[str, object]) -> Task:

Nastaví každé pole přes setattr a vrátí tentýž spravovaný objekt. Alias update_task_repository v service odlišuje tuto mechanickou funkci od stejně pojmenované service metody.

get_team_by_id

def get_team_by_id(db: Session, team_id: int) -> Team | None:

Načte Team primárním klíčem. Service z něj čte is_active při filtrování, přístupu i WIP kontrole.

get_team_member

def get_team_member(db: Session, team_id: int, user_id: int) -> TeamMember | None:

Vyhledá týmové členství podle identity uživatele. Create jej potřebuje k převodu user_id na cizí klíč creator_member_id.

is_team_member

def is_team_member(db: Session, team_id: int, user_id: int) -> bool:

Pomocí SQL EXISTS levně odpoví, zda členství existuje. Používají jej obě read access brány, když nepotřebují celý TeamMember.

get_team_member_by_id

def get_team_member_by_id(db: Session, team_id: int, member_id: int) -> TeamMember | None:

Ověří, že member ID skutečně patří danému týmu. Service jej používá pro assignee a reviewer při create, update i filtru; tyto opakované pomocné hrany jsou v grafu sloučeny.

get_in_progress_limit

def get_in_progress_limit(db: Session) -> int | None:

Čte singleton AppConfig s ID 1 a vrací jeho limit, nebo None. Chybějící konfiguraci interpretuje až service jako interní serverovou chybu.

Výběrový graf vztahů

Plné čáry jsou přímá volání. Graf vynechává konstruktory schémat, standardní knihovnu a opakované méně důležité validační hrany.

Textová alternativa: list vede přes resolver filtrů do čtení; create vede přes WIP kontrolu, pozici a insert; update vede do repository mutace; přístupová brána čte Task, členství a Team.
