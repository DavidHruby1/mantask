## DECISION 001: API fetching library

### Date
10-05-2026

### Context
- **Problem:** Mantask needs a reliable way to manage complex HTTP requests,
  including authentication and state-specific error handling.
- **Necessity:** To avoid code repetition across features like WIP limits, Debriefs, and Analytics.

### Decision
- **Selected Tool:** Axios.
- **Implementation:** Create a central instance configured for cookie-based sessions and global error management.

### Consequences
#### Positive
- **Efficiency:** Central configuration handles session cookies and error responses consistently.
- **UX:** Built-in timeout support and upload progress for task attachments.
- **Clean Code:** Automatic JSON parsing reduces boilerplate in data-heavy modules like Analytics.

#### Negative
- **Dependency:** Adds a small third-party package to the bundle.
- **Overhead:** Slight maintenance requirement compared to native solutions.

### Alternatives Considered
- **Fetch:** Rejected due to lack of built-in interceptors and the need for manual JSON/error handling.

### Authentication
- The backend uses server-side sessions transported in an `HttpOnly` cookie.
- The frontend does not store or inject JWTs.
- Cross-origin API requests must include credentials so the browser sends the session cookie.

### Notes
- This decision aligns with the "Developer-centric" and "Fast" philosophy of Mantask
  by prioritizing a clean, maintainable API layer that handles the "plumbing" of the app automatically.
